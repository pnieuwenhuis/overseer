# Repository knowledge lives in the repository, not in Overseer's settings

Everything specific to one repository lives inside that repository: prose guidance for agents (including repository-specific review guidance) in `AGENTS.md`, and the machine-readable build, test, setup and dependency commands in `.overseer.yml`, which is the Repository Manifest. Overseer's settings only record which repositories exist, plus the global Review Guidelines. We chose this over keeping commands in settings so that the knowledge is versioned with the code. A Task that changes the build can update the commands in the same commit, and other tools and humans read the same files. When a Repository in scope has no Repository Manifest, the Analyst adds a Task to create one, rather than anyone filling in a settings form.
